# API contract v1 — first workflow

Status: **draft**. Date: 2026-10-03. Base path: `/api/v1`.

This contract matches the M1 technical workflow checkpoint in [m1-plan.md](../m1-plan.md). It is not implemented, and it is not a live-customer API.

Driver-pay calculations are **disabled**. The server may store an integer the user typed. Typed amounts only. It must not compute driver pay, contribution, or reimbursement, and it must not execute a pay-formula table. Review does not write a ledger row.

Load handoffs, receipt-approval policy, and container empty returns are **Open**. This contract does not encode `lib/flow.ts` or `lib/finance.ts`.

## Conventions

- Auth is required. Session cookie or `Authorization: Bearer` for the same user. **Proposed** provider is Supabase Auth. The client does not send a role.
- Company scope is the caller’s organization. Driver scope is `profiles.driver_id`.
- Ids are UUIDs except `reference`.
- Every timestamp in a response is UTC (`2026-10-06T15:00:00Z`).
- The organization’s `displayTimezone` is an IANA name. Clients convert local input to UTC before sending, using that zone. Business-day query params are calendar dates in that zone. The server does not append a fixed `-07:00`.
- Money fields are integer cents. Omit them when the user did not type an amount. There is no server default.
- Content type: `application/json` except the file upload PUT, which uses the signed URL’s content type.

Errors:

```json
{ "error": { "code": "appointment_overlap", "message": "That driver already has a load in this window." } }
```

`code` is stable. A driver who must not see a row gets **404** `not_found`.

## Time and session

`GET /api/v1/me`

```json
{
  "profileId": "uuid",
  "organizationId": "uuid",
  "role": "owner",
  "driverId": null,
  "displayTimezone": "America/Los_Angeles"
}
```

`displayTimezone` is the org’s configured zone, echoed so the client can format UTC values and build business days. 401 `unauthenticated` when signed out.

`GET /api/v1/loads?businessDay=2026-10-06` keeps loads whose appointment interval intersects that calendar date in `displayTimezone`. The stored instants stay UTC.

## Load object

```json
{
  "id": "uuid",
  "reference": "SYN-LOAD-001",
  "containerNumber": null,
  "externalReference": null,
  "customerId": "uuid",
  "pickupPlaceId": "uuid",
  "destinationPlaceId": "uuid",
  "appointmentStart": "2026-10-06T15:00:00Z",
  "appointmentEnd": "2026-10-06T18:00:00Z",
  "lastFreeDay": null,
  "emptyReturnDeadline": null,
  "cutoff": null,
  "status": "created",
  "driverId": null,
  "truckId": null,
  "customerRateCents": null,
  "notes": "",
  "acknowledgedAt": null,
  "events": [],
  "documents": []
}
```

`status` is `created`, `assigned`, `accepted`, or `in_progress`.

`accepted` means the assigned driver acknowledged. `in_progress` means at least one progress event exists. Neither value means “empty returned” or “pay posted.”

Optional deadline fields are stored and do not create alerts.

Event:

```json
{
  "id": "uuid",
  "type": "progress",
  "fromStatus": "accepted",
  "toStatus": "in_progress",
  "actorProfileId": "uuid",
  "occurredAt": "2026-10-06T16:05:00Z",
  "note": "At the pickup door.",
  "reportedStage": null
}
```

`type` is `created`, `assigned`, `acknowledged`, or `progress`. `reportedStage` is optional text the driver sent. It is not validated against the pitch import or export list.

There is no `driverPay`, `contribution`, `estimatedHours`, or `earnings` field.

## POST /api/v1/loads

Owner only. Body matches the create fields on the load object (no `status`, no `events`).

| Result | Status | Code |
| --- | --- | --- |
| Created. One `created` event. | 201 | |
| Missing reference, customer, places, or appointment. End before start. | 422 | `invalid_load` |
| Duplicate `reference` in the org | 409 | `duplicate_reference` |
| Negative `customerRateCents` | 422 | `invalid_rate` |
| Driver | 403 | `forbidden` |
| Anonymous | 401 | `unauthenticated` |

`containerNumber` has no format check (D10).

## GET /api/v1/loads and GET /api/v1/loads/:id

Owner lists the org. A driver lists loads assigned to them. `GET` by id includes `events` (oldest first) and document metadata (no storage path).

Hidden or unknown ids are 404 `not_found`.

`GET /api/v1/loads/:id/events` returns `{ "events": [] }` with the same visibility.

## POST /api/v1/loads/:id/assign

Owner only. Body: `{ "driverId", "truckId" }`.

Allowed from `created` or `assigned`. Success sets `assigned` and appends one `assigned` event. No pay row.

| Result | Status | Code |
| --- | --- | --- |
| Assigned | 200 | |
| Status is `accepted` or `in_progress` | 409 | `load_not_assignable` |
| Driver off or inactive | 409 | `driver_unavailable` |
| Truck out of service | 409 | `truck_out_of_service` |
| Overlapping appointment on that driver or truck (`assigned`, `accepted`, or `in_progress`) | 409 | `appointment_overlap` |
| Driver session | 403 | `forbidden` |

Overlap is strict: touching at an endpoint (`end == other start`) is allowed.

## POST /api/v1/loads/:id/acknowledge

Assigned driver. Body `{}`.

| Result | Status | Code |
| --- | --- | --- |
| Was `assigned`. Now `accepted`. One `acknowledged` event. | 200 | |
| This driver already acknowledged (`accepted` or `in_progress`). No new event. | 200 | |
| Still `created` | 409 | `not_acknowledged` |
| Owner | 403 | `forbidden` |
| Other driver | 404 | `not_found` |

The owner sees the result by reading the load.

## POST /api/v1/loads/:id/progress

Assigned driver, and only after acknowledge. This is the progress update. It is not a step in the pitch state machine, and it does not require an empty return.

```json
{ "note": "Waiting at the gate.", "reportedStage": null }
```

`note` is required and non-blank. `reportedStage` is optional, at most 80 characters, stored as reported text.

| Result | Status | Code |
| --- | --- | --- |
| Appended. Status is `in_progress`. | 200 | |
| Blank note | 422 | `invalid_progress` |
| Load not yet acknowledged | 409 | `not_ready` |
| Owner or other driver | 403 or 404 | `forbidden` or `not_found` |

## Documents

Metadata only on the load. Bytes go to private storage.

### POST /api/v1/loads/:id/documents

Assigned driver, load is `accepted` or `in_progress`.

```json
{
  "kind": "receipt",
  "fileName": "toll.jpg",
  "mimeType": "image/jpeg",
  "byteSize": 180000,
  "amountCents": 1234
}
```

`kind` is `receipt` or `pod`. MIME is `image/jpeg`, `image/png`, or `application/pdf`. `byteSize` is 1 through 10485760. `amountCents` is required for `receipt`, omitted for `pod`, and must be ≥ 0. The amount is what the driver typed. It is not a pay rule.

| Result | Status | Code |
| --- | --- | --- |
| Row `pending`. Body includes `uploadUrl` (short-lived PUT) and `uploadHeaders`. | 201 | |
| Bad kind, mime, size, or amount | 422 | `invalid_document` |
| Load not acknowledged | 409 | `not_ready` |
| Owner | 403 | `forbidden` |

The PUT URL accepts only that content type and expires in minutes. The object key is `org/{organizationId}/loads/{loadId}/{documentId}`. The bucket is private.

### POST /api/v1/documents/:id/complete

Assigned driver, after the PUT succeeds. Marks the row stored. 409 `upload_missing` if the object is absent. Does not start a review decision and does not post money.

### GET /api/v1/documents/:id/file

Owner in the org, or the assigned driver. Returns a short-lived read URL or a streamed body. Other drivers and anonymous callers do not receive the URL (404 or 401).

### POST /api/v1/documents/:id/review

Owner only.

```json
{ "decision": "approved", "note": "" }
```

`decision` is `approved` or `rejected`. `rejected` requires a non-blank `note`.

| Result | Status | Code |
| --- | --- | --- |
| Review stored. `amountCents` unchanged. No ledger row. | 200 | |
| Upload not completed | 409 | `not_ready` |
| Driver | 403 | `forbidden` |

There is no `correction_requested` value in v1. That pitch state is not a customer-confirmed rule.

## Explicit non-responses

v1 has no pay-rule, ledger, invoice, settlement, map, or customs endpoint. A handler that computed driver pay from `customerRateCents`, from a receipt amount, or from the constants in `lib/reference.ts` would violate this contract. A handler that blocked progress until an empty return would also violate it.
